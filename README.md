# ภารกิจตะลุยโจทย์ปัญหา "อนุกรมเลขคณิต"

เว็บแอปพลิเคชันเพื่อการเรียนรู้แบบ gamification สำหรับห้องเรียนคณิตศาสตร์
แบ่งนักเรียนเป็น 6 กลุ่ม ตะลุยโจทย์ 7 ข้อ โดยแต่ละข้อถูกซอยเป็น **บันไดคำถามย่อย**
ที่พานักเรียนคิดทีละขั้นจนถึงคำตอบ ครูติดตามความก้าวหน้าได้แบบเรียลไทม์ผ่านกระดานแยกต่างหาก

---

## โครงสร้างไฟล์

```
.
├── เริ่มเกม.command         ตัวเปิดเกม — ดับเบิลคลิกไฟล์นี้ได้เลย (macOS)
├── index.html              หน้าแรก — เลือกบทบาท (นักเรียน / ครู)
├── student.html            หน้าจอนักเรียน (3 ฉาก: เลือกกลุ่ม → เล่น → สรุปผล)
├── teacher.html            กระดานครู
├── assets/                 ภาพประกอบโจทย์ (SVG ทั้งหมด 7 ภาพ)
│   ├── chairs.svg  saving.svg  logs.svg  buttons.svg
│   └── rocket.svg  installment.svg  walk.svg
├── css/
│   └── styles.css          สไตล์ทั้งระบบ แบ่งเป็น 7 หมวด
├── js/
│   ├── config.js           ไฟล์ตั้งค่าเดียว — ใส่ API Key และปรับกติกาที่นี่
│   ├── questions.js        คลังโจทย์ + บันไดคำถามย่อย + เฉลย (ครูแก้ไฟล์นี้ไฟล์เดียวพอ)
│   ├── icons.js            ชุดไอคอน SVG (ใช้แทน emoji ทั้งระบบ)
│   ├── backend.js          ชั้นข้อมูล (Firebase / โหมดออฟไลน์) ซ่อนหลัง interface เดียว
│   ├── student.js          ตรรกะเกมฝั่งนักเรียน
│   └── teacher.js          ตรรกะกระดานครู
├── database.rules.json     Security Rules พร้อมคัดลอกไปวางใน Firebase Console
└── README.md
```

**หลักการออกแบบ:** เนื้อหา (`questions.js`) · การตั้งค่า (`config.js`) · ข้อมูล (`backend.js`) · การแสดงผล (`student.js` / `teacher.js`)
แยกจากกันโดยสิ้นเชิง — เปลี่ยนโจทย์ไม่ต้องแตะโค้ดเกม เปลี่ยนจาก Firebase ไปใช้บริการอื่นก็แก้แค่ `backend.js`

**ไม่ใช้ emoji ในหน้าเว็บ** ทั้งระบบใช้ไอคอน SVG จาก `js/icons.js` เพราะ emoji หน้าตาต่างกันในแต่ละ
ระบบปฏิบัติการ ควบคุมสีและขนาดไม่ได้ และโปรแกรมอ่านหน้าจออ่านได้ไม่ดี

## หัวใจของระบบ: Scaffolding แบบ "พาเดินทีละขั้น"

แต่ละข้อ **ไม่ได้ถามคำตอบสุดท้ายทันที** แต่ซอยเป็นขั้นย่อยที่นักเรียนต้อง *ตอบ* ทีละขั้น
ตอบขั้นไหนถูก ระบบยืนยันด้วยคำอธิบายสั้น ๆ แล้วปลดล็อกขั้นถัดไปให้เอง

```
ขั้นที่ 1   อ่านโจทย์ให้ออกว่าอะไรคือ a₁ และ d        (แปลงสถานการณ์เป็นลำดับ)
ขั้นที่ 2   เลือกเครื่องมือให้ถูก                      (จะใช้ aₙ หรือ Sₙ)
ขั้นที่ 3   แทนค่า / จัดรูปสมการ                      (ลงมือคำนวณขั้นกลาง)
ขั้นสุดท้าย ตอบคำถามที่โจทย์ถามจริง ๆ
```

นักเรียนจึงถูก "พา" ไปถึงคำตอบ แทนที่จะอ่านคำใบ้แล้วถูกปล่อยให้คิดต่อเอง
ขั้นที่ผ่านแล้วจะยุบเหลือคำตอบกับคำอธิบาย ทำให้เห็นเส้นทางการคิดทั้งหมดเรียงต่อกัน

### กติกาและคะแนน

| หัวข้อ | ค่าที่ตั้งไว้ | แก้ได้ที่ |
|---|---|---|
| จำนวนกลุ่ม | 6 กลุ่ม | `APP_CONFIG.groupCount` |
| พลังชีวิต | 3 ดวง **ต่อหนึ่งข้อ** (ไม่ใช่ต่อขั้น) เริ่มใหม่ทุกข้อ | `APP_CONFIG.maxHearts` |
| ตอบผิดครบกี่ครั้งจึงเฉลยทั้งข้อ | 5 ครั้ง | `APP_CONFIG.revealAfterWrong` |
| คะแนนเต็มต่อข้อ | 100 | `APP_CONFIG.basePoints` |
| หักต่อการตอบผิด 1 ครั้ง | 20 | `APP_CONFIG.penaltyPerWrong` |
| หักต่อการกดขอคำใบ้ 1 ครั้ง | 10 | `APP_CONFIG.penaltyPerHint` |
| คะแนนขั้นต่ำถ้ายังทำสำเร็จ | 20 | `APP_CONFIG.minPoints` |
| PIN ปุ่มรีเซ็ต | `1234` | `APP_CONFIG.teacherPin` |

**จังหวะเมื่อตอบผิด**

1. ผิดครั้งที่ 1 → เสียพลังชีวิต 1 ดวง + ระบบเปิด **คำใบ้ของขั้นนั้น** ให้อัตโนมัติ (ยังไม่เฉลย)
2. ผิดครั้งที่ 2 → เสียพลังชีวิตอีก 1 ดวง
3. ผิดครั้งที่ 3 → **พลังชีวิตหมด ข้อนี้ได้ 0 คะแนน แต่ยังเดินบันไดต่อจนจบได้** เพื่อให้ยังเรียนรู้
4. ผิดครั้งที่ 4 → ยังไม่เฉลย ให้ลองอีกครั้ง
5. ผิดครั้งที่ 5 → ระบบเฉลยทั้งข้อพร้อมวิธีทำเต็ม แล้วไปข้อถัดไป

นักเรียนกด **"ขอคำใบ้"** เองได้ตลอด — ไม่เสียพลังชีวิต แต่หักคะแนน 10
(ออกแบบไว้ให้กลุ่มที่ติดจริงกล้าขอความช่วยเหลือ แทนที่จะเดามั่วจนพลังชีวิตหมด)

## ลำดับโจทย์ 7 ข้อ

เรียงจาก "แทนค่าในสูตรตรง ๆ" ไปสู่ "ต้องตีความและแก้หลายขั้น"

| ด่าน | ชื่อ | ทักษะหลัก | ขั้นย่อย | คำตอบ |
|:--:|---|---|:--:|---|
| 1 | ห้องประชุมสัมมนา | หา Sₙ ตรง ๆ จาก a₁, d, n | 4 | 580 ตัว |
| 2 | เงินออมของนาธาน | ตีความว่า n = 12 จากเดือน ม.ค.–ธ.ค. | 4 | 42,600 บาท |
| 3 | กองไม้ซุง | หา n จาก aₙ ก่อน แล้วค่อยหา Sₙ | 4 | 22,969 ท่อน |
| 4 | กระดุมรูปสามเหลี่ยม | แปลงหน่วย → แก้สมการหา n → ตอบ aₙ | 4 | 19 เม็ด |
| 5 | ปล่อยจรวด | d เป็นลบ + สมการกำลังสองที่มีสองคำตอบใช้ได้ทั้งคู่ | 5 | 7 และ 12 วินาที |
| 6 | ผ่อนคอมพิวเตอร์ | หาค่างวดรวมเป็นลำดับ + ดักกับดัก n = 25 ไม่ใช่ 30 | 5 | 56,500 บาท |
| 7 | โจเดินไล่ตามเจ | เศษส่วน + ตั้งสมการสองฝั่ง + ตอบ aₙ ไม่ใช่ n | 5 | 7.5 กม./ชม. |

ขั้นที่คำตอบเป็นทศนิยมหรือมีกับดัก (ข้อ 5 และ 7) ใช้ **ปรนัย**
ส่วนขั้นที่คำตอบเป็นจำนวนเต็มใช้ **พิมพ์ตัวเลข** (รับการพิมพ์ลูกน้ำคั่นหลักพันด้วย เช่น `42,600`)

### หมายเหตุทางวิชาการ 2 จุด

### ⚠️ ข้อ 6 (ผ่อนคอมพิวเตอร์) — เฉลยในเอกสารต้นฉบับคำนวณผิด

เฉลยที่แจกมาใช้ **n = 30** แล้วได้ 66,300 บาท ซึ่ง **ไม่ถูกต้อง**

ผ่อนเงินต้นเดือนละ 2,000 บาท จาก 50,000 บาท จะหมดที่ **งวดที่ 25** พอดี
หลังจากนั้นยอดค้างเป็นศูนย์ ไม่มีทั้งเงินต้นและดอกเบี้ยให้จ่ายอีก

| งวด | ยอดค้างก่อนจ่าย | เงินต้น | ดอกเบี้ย 1% | จ่ายงวดนี้ |
|---:|---:|---:|---:|---:|
| 1 | 50,000 | 2,000 | 500 | 2,500 |
| 2 | 48,000 | 2,000 | 480 | 2,480 |
| 24 | 4,000 | 2,000 | 40 | 2,040 |
| 25 | 2,000 | 2,000 | 20 | 2,020 |
| 26–30 | 0 | 0 | 0 | **0** |

- ใช้ n = 25 ⇒ S₂₅ = 12.5 × 4,520 = **56,500 บาท** ✅ (ตรวจทาน: เงินต้น 50,000 + ดอกเบี้ย 6,500)
- ใช้ n = 30 ⇒ S₃₀ = 15 × 4,420 = 66,300 บาท ❌ เท่ากับจ่ายเงินต้นรวม 60,000 บาท
  ทั้งที่เครื่องราคา 50,000 บาท

คำว่า "ภายในเวลา 30 เดือน" เป็น **กรอบเวลาที่กำหนด** ไม่ใช่จำนวนงวด
เว็บแอปจึงใช้ 56,500 และเพิ่มขั้นย่อยให้นักเรียนหา n เองก่อน เพื่อดักกับดักนี้โดยเฉพาะ

### ข้อ 5 (ปล่อยจรวด) — ตอบสองค่า

n = 7 และ n = 12 ให้ Sₙ = 210 ทั้งคู่ จึงเป็นคำตอบที่ใช้ได้ทั้งสองค่า (ตรงกับเฉลยต้นฉบับ)
พจน์ที่ 10 มีค่า 0 คือจรวดขึ้นถึงจุดสูงสุด 225 ไมล์ หลังจากนั้นพจน์เป็นลบ
จรวดจึงตกกลับลงมาผ่านระดับ 210 ไมล์อีกครั้งที่วินาทีที่ 12

### การแก้ไขภาพประกอบ

ทุกข้อมีภาพ SVG ของตัวเองอยู่แล้วในโฟลเดอร์ `assets/`
ภาพเหล่านี้ตั้งใจออกแบบให้อธิบาย **สถานการณ์** เท่านั้น ไม่เฉลยคำตอบ
ถ้าต้องการเปลี่ยนเป็นรูปถ่ายหรือภาพอื่น แก้ฟิลด์ `image` ใน `js/questions.js`:

```js
image: {
  src: 'assets/rocket.svg',          // หรือ URL เต็มจากอินเทอร์เน็ต
  alt: 'แผนภาพจรวดไต่ระดับความสูง',   // คำอธิบายสำหรับโปรแกรมอ่านหน้าจอ
  caption: 'ระยะที่ไต่ขึ้นได้ลดลงวินาทีละ 5 ไมล์',
},
```

## การตั้งค่า Firebase (ทีละขั้น)

### ขั้นที่ 1 — สร้างโปรเจกต์และฐานข้อมูล

1. เข้า <https://console.firebase.google.com> → **Add project** → ตั้งชื่อ เช่น `arith-series-class`
   (ปิด Google Analytics ได้ ไม่จำเป็นสำหรับงานนี้)
2. เมนูซ้าย → **Build → Realtime Database** → **Create Database**
3. เลือก location **Singapore (asia-southeast1)** — ใกล้ไทยที่สุด ดีเลย์ต่ำสุด
4. เลือก **Start in locked mode** (เดี๋ยวใส่กฎเองในขั้นที่ 3)

### ขั้นที่ 2 — เอาค่า config มาใส่

1. ไอคอนเฟือง → **Project settings** → เลื่อนลงหา **Your apps** → กดไอคอน `</>` (Web)
2. ตั้งชื่อเล่นแอป → **Register app** (ไม่ต้องติ๊ก Firebase Hosting)
3. จะได้โค้ด `firebaseConfig = { ... }` ให้คัดลอกค่าทั้งหมดไปวางทับใน **`js/config.js`**

```js
export const FIREBASE_CONFIG = {
  apiKey: 'AIzaSy...',
  authDomain: 'arith-series-class.firebaseapp.com',
  databaseURL: 'https://arith-series-class-default-rtdb.asia-southeast1.firebasedatabase.app',
  projectId: 'arith-series-class',
  storageBucket: 'arith-series-class.appspot.com',
  messagingSenderId: '123456789012',
  appId: '1:123456789012:web:abc123',
};
```

> ถ้า `databaseURL` ไม่มีในโค้ดที่ Firebase ให้มา ให้คัดลอกจากหน้า Realtime Database โดยตรง
> (บรรทัดบนสุดที่ขึ้นต้นด้วย `https://...firebasedatabase.app`)

### ขั้นที่ 3 — วาง Security Rules

Realtime Database → แท็บ **Rules** → ลบของเดิมทิ้ง → วางเนื้อหาจากไฟล์ **`database.rules.json`** → **Publish**

กฎชุดนี้ทำ 3 อย่าง:

- **ล็อกขอบเขต** — เขียนได้เฉพาะใต้ `rooms/<รหัสห้อง>/groups/group-1` ถึง `group-6` เท่านั้น นอกนั้นเขียนไม่ได้เลย
- **บังคับรูปร่างข้อมูล** — `totalScore` ต้องเป็นตัวเลข 0–10,000 คำตอบที่ผิดต้องเป็นข้อความไม่เกิน 60 ตัวอักษร ฯลฯ
  ป้องกันคนยิงข้อมูลก้อนใหญ่เข้ามาถล่มโควตาฟรี
- **ปฏิเสธฟิลด์แปลกปลอม** — `"$other": { ".validate": false }` ทำให้เพิ่ม key ที่ไม่ได้ออกแบบไว้ไม่ได้

### ขั้นที่ 4 — อัปโหลดขึ้น GitHub Pages

```bash
git init
git add .
git commit -m "เพิ่มเกมอนุกรมเลขคณิต"
git branch -M main
git remote add origin https://github.com/<ชื่อผู้ใช้>/<ชื่อ-repo>.git
git push -u origin main
```

จากนั้นใน GitHub: **Settings → Pages → Source: Deploy from a branch → main / (root) → Save**
รอประมาณ 1–2 นาที จะได้ลิงก์ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ-repo>/`

## ความปลอดภัย — ป้องกัน API Key รั่วไหล

### เข้าใจก่อนว่า "Firebase API Key ไม่ใช่รหัสลับ"

นี่คือจุดที่คนเข้าใจผิดกันมากที่สุด Google ระบุไว้เองว่า Firebase Web API Key
**ถูกออกแบบมาให้เปิดเผยต่อสาธารณะ** — มันทำหน้าที่แค่ "บอกว่านี่คือโปรเจกต์ไหน" ไม่ใช่ "รหัสผ่านเข้าใช้งาน"
ใครก็ตามที่เปิดเว็บแล้วกด View Source จะเห็นค่านี้เสมอ ไม่ว่าจะซ่อนอย่างไร
(เอาไปใส่ `.env` แล้ว build ด้วย Vite/Webpack ก็ยังถูกฝังลงไฟล์ JS อยู่ดี)

**กำแพงกันภัยจริง ๆ จึงไม่ได้อยู่ที่การซ่อนคีย์ แต่อยู่ที่ 3 ชั้นนี้:**

### ชั้นที่ 1 — Security Rules (สำคัญที่สุด)

ด่านที่ "ตัดสินจริง" ว่าใครอ่าน/เขียนอะไรได้ ทำตามขั้นที่ 3 ข้างบนให้เรียบร้อย

**สิ่งที่ห้ามทำเด็ดขาด** คือปล่อยกฎเป็นแบบนี้ (โหมดทดสอบของ Firebase):

```json
{ "rules": { ".read": true, ".write": true } }
```

เพราะใครก็ได้บนอินเทอร์เน็ตจะลบฐานข้อมูลทั้งก้อนได้ด้วยคำสั่งเดียว
และ Firebase จะส่งอีเมลเตือนภายใน 24 ชั่วโมงด้วย

### ชั้นที่ 2 — จำกัดโดเมนที่เรียกใช้คีย์ได้ (HTTP Referrer)

กันคนก๊อปคีย์ไปใช้บนเว็บของตัวเอง

1. ไปที่ <https://console.cloud.google.com/apis/credentials> แล้ว **เลือกโปรเจกต์เดียวกัน** กับ Firebase
2. ในตาราง **API Keys** จะเห็นคีย์ชื่อ *Browser key (auto created by Firebase)* → กดเข้าไป
3. หัวข้อ **Application restrictions** → เลือก **Websites**
4. กด **ADD** แล้วใส่โดเมนที่อนุญาตให้ครบทุกบรรทัด:

   ```
   https://<ชื่อผู้ใช้>.github.io/*
   http://localhost:*/*
   http://127.0.0.1:*/*
   ```

5. กด **SAVE** — รอประมาณ 5 นาทีให้การตั้งค่ามีผล

> **อย่าเพิ่งไปยุ่งกับหัวข้อ API restrictions** ที่อยู่ถัดลงมา
> คีย์ตัวนี้ Firebase สร้างให้อัตโนมัติและใช้ร่วมกันหลายบริการ
> ถ้าไปติ๊กจำกัดรายการ API เอง มักทำให้บางส่วนของ Firebase ใช้งานไม่ได้ขึ้นมาเฉย ๆ
> และหาสาเหตุยากมาก สำหรับงานนี้ **Application restrictions อย่างเดียวพอแล้ว**

> **ข้อควรระวัง:** ถ้าใส่โดเมนไม่ครบ คำขอจากหน้าที่ไม่ได้อยู่ในรายการจะถูกบล็อกทันที
> (รวมถึงตอนทดสอบในเครื่อง ถ้าลืมใส่ `localhost`) อาการคือเว็บเปิดได้แต่ข้อมูลไม่ขึ้น
> และใน Console ของเบราว์เซอร์จะขึ้นข้อความประมาณ `requests from referrer ... are blocked`
>
> **ข้อควรรู้:** HTTP Referrer เป็นค่าที่เบราว์เซอร์ส่งมา จึงปลอมได้ด้วยเครื่องมืออย่าง `curl`
> มันจึงเป็น "ด่านกันคนทั่วไป" ไม่ใช่ "ด่านกันแฮกเกอร์" — **Security Rules เท่านั้นที่กันได้จริง**
> อย่าใช้ชั้นที่ 2 แทนชั้นที่ 1 เด็ดขาด

## ทดลองใช้งานก่อนตั้งค่า Firebase

ระบบมี **โหมดออฟไลน์** ในตัว — ถ้ายังไม่ได้ใส่คีย์ใน `config.js` ข้อมูลจะถูกเก็บลง `localStorage`
และซิงก์ข้ามแท็บในเครื่องเดียวกันผ่าน `BroadcastChannel`
(เปิดหน้านักเรียนกับกระดานครูคู่กันเพื่อดูการอัปเดตได้ทันที)

### สำคัญ: ห้ามดับเบิลคลิก `index.html` ตรง ๆ

โค้ดใช้ **ES Modules** ซึ่งเบราว์เซอร์บล็อกเมื่อเปิดไฟล์จากฮาร์ดดิสก์โดยตรง (`file://`)
ด้วยเหตุผลด้านความปลอดภัย ถ้าเปิดแบบนั้นจะเห็นหน้าว่าง ๆ ไม่มีปุ่มอะไรเลย
(ตอนนี้ระบบจะขึ้นกล่องเตือนพร้อมวิธีแก้ให้แทนหน้าว่าง)

**วิธีที่ 1 — ดับเบิลคลิก `เริ่มเกม.command`** (ง่ายที่สุด)

ไฟล์นี้จะหาพอร์ตว่างให้เอง เปิดเซิร์ฟเวอร์ แล้วเปิดเบราว์เซอร์ให้อัตโนมัติ
หน้าต่าง Terminal ที่เด้งขึ้นมาคือตัวเซิร์ฟเวอร์ — **อย่าปิดระหว่างใช้งาน**
เลิกใช้แล้วกด `Ctrl + C` หรือปิดหน้าต่างนั้นได้เลย

**วิธีที่ 2 — สั่งเองผ่าน Terminal**

```bash
cd "$HOME/Desktop/โจทย์ปัญหาอนุกรม เลขคณิต" && python3 -m http.server 8000
```

แล้วเปิด <http://localhost:8000>

**วิธีที่ 3 — อัปขึ้น GitHub Pages** แล้วเปิดลิงก์ `https://` ได้ตรง ๆ ไม่ต้องรันอะไรเลย
(จำเป็นอยู่แล้วถ้าต้องการให้นักเรียนใช้คนละเครื่อง)

## เคล็ดลับการใช้สอน

- ฉายกระดานครูขึ้นจอหน้าห้อง — ตาราง "กลุ่ม × ข้อ" กลายเป็น leaderboard สร้างแรงจูงใจในตัว
- ช่องสีส้มในตารางจะบอกด้วยว่ากลุ่มนั้นเดินมาถึง **ขั้นที่เท่าไรของบันได** เช่น `2/4`
  ถ้าหลายกลุ่มค้างที่ขั้นเดียวกัน นั่นคือจุดที่ควรหยุดอธิบายรวมทั้งห้อง
- ตัวเลขแดงมุมขวาบนของช่อง = จำนวนครั้งที่ตอบผิดในข้อนั้น
- กด **"ดูคำตอบที่ผิด"** ในการ์ดรายกลุ่ม จะเห็นว่าผิดที่ **ขั้นไหน** และตอบอะไรไป
  เช่น ถ้าหลายกลุ่มผิดที่ "ขั้นที่ 2 เลือกเครื่องมือ" แปลว่าเด็กยังแยกไม่ออกระหว่าง aₙ กับ Sₙ
  — เป็นข้อมูลวินิจฉัยที่ตรงจุดกว่าการดูแค่คำตอบสุดท้าย
- ค่า **"ข้อที่สะดุดมากที่สุด"** บนแถบ KPI ใช้สรุปท้ายคาบได้เลยว่าควรทบทวนเรื่องใด
